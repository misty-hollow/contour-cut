### P-003 게임 콘셉트와 첫 개발 목표 — 사용자 요청 2026-10-14
- 콘셉트: "2D 평면 지도의 등고선을 베어 3차원 공간의 높낮이를 왜곡한다." 탑다운 스타일리시 액션. 어두운 배경 + 형광 등고선의 강렬한 픽셀아트 감성(산나비에서 영감, 독창적 정체성). 세계는 종이 지도처럼 접히는 기형 단층 지대, 주인공은 등고선을 보는 검은 측량사.
- 핵심 재미: 적을 직접 공격하는 것보다 지형을 공격해 전투 상황을 바꾸는 것.
- 이번 목표: 최소 플레이 가능 프로토타입. 필수 상호작용 3개 — 등고선 절단(고도차 변화), 적 낙하·이동 방해, 고도차를 이용한 지형 이동·회피. 실시간 3D 메시 변형은 하지 않는다.
- 범위 밖: 완성 게임, 거대한 시스템, 복잡한 세계관, 다수 스테이지.
- 재미·조작감·비주얼 방향의 최종 판단은 사용자(CLAUDE.md D절).

### P-004 부트스트랩만 main에 직접 반영 — 승인 2026-10-14 (사용자 지시)
- "저장소 생성 후 초기 부트스트랩을 진행하고, 이후에는 작업 브랜치와 PR 중심으로 운영". 빈 저장소에는 PR의 기준이 될 main이 없으므로 첫 commit(운영 문서만, 코드·의존성 없음)만 main에 push하고, 직후 main 보호를 건다. 그 뒤 모든 변경은 PR.
- GitHub 최초 설정(main 보호, 자동 삭제, 병합 방식)은 이 지시("가능한 범위에서 main 브랜치 보호, 테스트, CI, 보고 체계를 설정")로 메인이 수행한다. 이후 설정 변경은 CLAUDE.md E절 승인 대상.

## 기술 결정 (AI 위임)

### T-001 스택: TypeScript + Vite + Canvas 2D, 게임 엔진 없음 — 2026-10-14
- 이유: 필요한 것은 격자 높이 데이터, 2.5D 그리기, 키보드·마우스 입력뿐이다. 엔진 없이 파일 몇 개로 끝나고, 규칙을 순수 함수로 두면 Vitest로 결정적 시험이 된다. 브라우저라 사용자가 설치 없이 실행하고, Playwright로 실제 입력→화면 검증을 CI까지 돌릴 수 있다.
- 거부한 대안: Godot(편집기·내보내기 바이너리, AI가 실제 입력 검증을 돌리기 어렵다), Phaser(장면·물리 체계가 이번 범위에 불필요한 표면적), PixiJS·three.js(WebGL — headless 렌더링 차이, 3D 불필요).

### T-002 의존성은 출시 2주 이상 지난 버전으로 고정 — 2026-10-14
- 이유: 공급망 위험. 최신 표기만 보고 갓 나온 버전을 쓰지 않는다. TypeScript는 typescript-eslint 지원 범위(`<6.1`) 때문에 6.0.x.

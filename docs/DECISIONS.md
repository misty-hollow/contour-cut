- 핵심 재미: 적을 직접 공격하는 것보다 지형을 공격해 전투 상황을 바꾸는 것.
- 이번 목표: 최소 플레이 가능 프로토타입. 필수 상호작용 3개 — 등고선 절단(고도차 변화), 적 낙하·이동 방해, 고도차를 이용한 지형 이동·회피. 실시간 3D 메시 변형은 하지 않는다.
- 범위 밖: 완성 게임, 거대한 시스템, 복잡한 세계관, 다수 스테이지.
- 재미·조작감·비주얼 방향의 최종 판단은 사용자(CLAUDE.md D절).

### P-004 부트스트랩만 main에 직접 반영 — 승인 2026-10-14 (사용자 지시)
- "저장소 생성 후 초기 부트스트랩을 진행하고, 이후에는 작업 브랜치와 PR 중심으로 운영". 빈 저장소에는 PR의 기준이 될 main이 없으므로 첫 commit(운영 문서만, 코드·의존성 없음)만 main에 push하고, 직후 main 보호를 건다. 그 뒤 모든 변경은 PR.
- GitHub 최초 설정(main 보호, 자동 삭제, 병합 방식)은 이 지시("가능한 범위에서 main 브랜치 보호, 테스트, CI, 보고 체계를 설정")로 메인이 수행한다. 이후 설정 변경은 CLAUDE.md E절 승인 대상.

### P-006 공식 세계관 초안과 용어 — 승인 2026-10-14 (사용자 제공)
- 대접힘(The Folding), 절대 심연(Zero Datum), 주인공 카인(The Black Cartographer)과 측량도(Contour Cutter), 목표 원점 타워(Benchmark Zero), 적대 세력(무장 세력·왜곡 방위대). 원문 정리는 `docs/WORLD.md`.
- 용어: 측량 절단(Survey Cut), 단층 침하(Fault Subsidence), 지형 환원(Restoration), 절대 심연(Zero Datum), 표고(Elevation).
- 반영 원칙: HUD·화면은 자연스러운 곳만, 익숙한 조작 안내를 해치는 변경은 피함, 코드 식별자·주석은 바꾸지 않음.
- 미확정으로 남김: 적대 세력이 지형 복구에 반대하는 이유.

### P-007 지형 환원 에어본 콤보 — 승인 2026-10-14 (사용자 요청)
- 기존 7초 복구를 그대로 쓴다. 침하 지형이 원래 표고로 돌아오는 순간 그 위의 적이 공중으로 튕겨 오르고 짧게 무방비가 된다. 그동안 추가 공격 가능. 복구 자체로 즉사하지 않는다.
- 핵심 루프: 측량 절단 → 적 낙하·고립 → 지형 환원 → 에어본 → 추가 공격.
- 수치(튕김 세기 15, 무방비 = 체공 + 0.4초, 공중 추가타 2 피해)는 AI가 정한 초기값이며 체감은 사용자 판단 항목.

## 기술 결정 (AI 위임)

### T-001 스택: TypeScript + Vite + Canvas 2D, 게임 엔진 없음 — 2026-10-14
- 이유: 필요한 것은 격자 높이 데이터, 2.5D 그리기, 키보드·마우스 입력뿐이다. 엔진 없이 파일 몇 개로 끝나고, 규칙을 순수 함수로 두면 Vitest로 결정적 시험이 된다. 브라우저라 사용자가 설치 없이 실행하고, Playwright로 실제 입력→화면 검증을 CI까지 돌릴 수 있다.
- 거부한 대안: Godot(편집기·내보내기 바이너리, AI가 실제 입력 검증을 돌리기 어렵다), Phaser(장면·물리 체계가 이번 범위에 불필요한 표면적), PixiJS·three.js(WebGL — headless 렌더링 차이, 3D 불필요).

### T-002 의존성은 출시 2주 이상 지난 버전으로 고정 — 2026-10-14
- 이유: 공급망 위험. 최신 표기만 보고 갓 나온 버전을 쓰지 않는다. TypeScript는 typescript-eslint 지원 범위(`<6.1`) 때문에 6.0.x. ESLint 9.39는 지원 종료 표시라 10.11.
- 고정 버전: vite 8.3.1, vitest 5.0.2, typescript 6.0.3, eslint 10.11.0, @eslint/js 10.0.1, typescript-eslint 8.70.1, globals 17.12.0, @playwright/test 1.63.0, @types/node 24.13.6.

### T-003 지형 = 정수 고도 격자 + 2.5D 경사 투영 — 2026-10-14
- 80×41칸(칸당 6px), 고도 0~6 정수, 심연 = 음수. 화면은 내부 480×270을 정수 배율로 확대(픽셀아트). 고도 1단계 = 화면 위로 4px, 남쪽 줄을 나중에 그려 높은 앞 지형이 뒤를 가린다.
- 등고선 = 고도가 다른 칸 사이 경계. 높은 쪽 칸 테두리에 그 고도의 형광색으로 긋는다. 심연 테두리는 경고 적색.
- 거부한 대안: 실시간 3D 메시 변형(P-003에서 불필요), marching squares 곡선 등고선(픽셀 감성과 맞지 않고 칸 단위 규칙과 어긋남 — 비주얼 방향이 정해지면 다시 검토).

### T-004 시뮬레이션은 고정 1/60초 간격, 규칙은 순수 로직 — 2026-10-14
- `World.step(dt, input)`이 시간·입력만으로 결정된다(시드 RNG). 그리기 연출만 `Math.random`. 그래서 단위 테스트가 결정적이고, 같은 시드·입력은 같은 결과(테스트로 고정).

### T-006 카메라·타격 연출은 표시 단계에서만 — 2026-10-14
- 게임 화면은 지금까지처럼 480×270 픽셀 화면에 그리고, 표시 캔버스로 정수 배율 k(화면 배율 × 기기 픽셀 비율)로 옮길 때 줌·흔들림을 적용한다. 줌 1·흔들림 0이면 이전 화면과 픽셀 단위로 같다(P-005 보존).
- 줌: 고지대→저지대 대시 활강 중 최대 6% 줌아웃, 주요 타격 순간 1.5~4.5% 줌인(0.12초). 흔들림은 시간에 따라 잦아든다. 배율 `tune.zoomFx`·`tune.shake`, "연출 줄이기" 체크박스, 운영체제 동작 줄이기 설정이면 처음부터 끔.
- 마우스 조준은 줌을 역변환해 읽고 흔들림은 무시한다(조준이 떨리지 않게). 관찰 핸들 `__cc.project`도 같은 변환을 쓴다.
- 타격 멈춤: 일반 절단·타격 0.05초(기존), 처치·공중 추가타·2단 이상 착지 0.06초. 겹치면 긴 쪽 하나(누적 없음). 멈춘 동안 게임 시간이 흐르지 않아 7초 환원은 게임 시간 기준 그대로이고, 들어온 대시 입력은 보존된다.
- 거부한 대안: 줌을 480×270 안에서 다시 샘플링(픽셀이 뭉개짐), CSS transform 줌(HUD·입력 좌표까지 같이 움직임).

### T-007 폐곡선 절단 보너스 확장 검토(구현하지 않음) — 2026-10-14
- 가능성: 칼날 경로가 같은 고도의 등고선 고리를 둘러싸면(여러 번의 절단 궤적을 이어 닫힌 다각형) 그 안쪽 고지대 전체를 반경 제한 없이 침하시키는 보너스. 현재 구조에서는 `Terrain.findCrossings`가 칸 경계만 보므로, 절단 궤적을 시간 창(예: 1.5초) 안에서 이어 붙이는 기록과 "고리 안쪽" 판정(다각형 내부 칸 채우기)이 추가로 필요하다.
- 위험: 한 번에 넓은 지역이 사라져 P-005의 전투 밀도·난이도 체감이 바뀔 수 있다. 도입하면 핵심 규칙 의미 변경이라 고위험·사용자 결정.

### T-005 검증 체계 — 2026-10-14
- 단위(Vitest): 지형 규칙·길찾기·적 낙하·지형 이동·회피·게임 오버.
- 플레이 경로(Playwright): 프로덕션 빌드에서 실제 마우스·키보드로 시작 → 절단 → 낙하·심연·구덩이 → 대시 충격파 → 엄폐 → 게임 오버 → 재시작. 상태 관찰과 좌표 변환만 디버그 핸들 `window.__cc`로, 초기 배치는 `?scenario=`로.
- CI에서 둘 다 돈다(ubuntu, chromium). 외부 업로드 없음.
